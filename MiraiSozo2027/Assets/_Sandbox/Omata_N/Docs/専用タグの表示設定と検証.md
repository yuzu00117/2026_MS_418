# 専用タグによるエコーロケーション表示

## 設定方法

対象の EchoTarget に専用タグアセットを指定し、そのアセットのインスペクターを編集する。作成メニューは「エコーロケーション / 専用タグ」。EchoController の旧タグ一覧・Unityタグでは表示を設定しない。同じアセットを使う対象は表示設定を共有する。

日本語の3つの区画で、①塗りつぶし ②アウトライン ③元マテリアルを独立して設定する。各区画には以下がある。

- 表示する
- 壁越しに表示する
- 表示範囲：接触した部分 / オブジェクト全体
- 接触終了後も表示を残す
- 残存時間（秒）

表示範囲は接触中と残存中の両方に使う。「接触した部分」は各表面が最後に接触した時点から、「オブジェクト全体」は対象のどこかが最後に接触した時点から計時する。

グリッチノイズの表示は廃止した（2026-10-28）。関連する設定・シェーダーのパス・コンポーネント（EchoGlitch）・デモシーンの作成メニューは削除済み。既存のタグアセットに残る `_glitch` の値は読み込まれず、Unityで保存し直すと消える。

専用タグのない物体はエコーの遮断対象。専用タグがある物体はアセットの「エコーロケーションを遮断する」に従う。表示をすべて無効にして遮断専用にもできる。旧 EchoOccluder、Unityタグ別遮断設定、旧遮断レイヤー設定は判定に使わない。発信源側の遮蔽有効設定と除外ルートは引き続き適用する。「壁越し表示」はカメラからの遮蔽に対する設定で、発信源から壁で遮断されたエコーを貫通させる設定ではない。

## 検証用シーン

Scenes/Scene_EchoTagEffectsDemo.unity を開いて再生する。左から塗りつぶし、アウトライン、元マテリアルの対象を配置。Settings/EchoGlitchDemo/SO_Effect0～2.asset が対応する設定（フォルダ名は既存の参照を保つため変更していない）。デモの操作コンポーネントは EchoDemoDriver。Gameビューの操作でエコーを開始・停止できる。
デモ専用のURP設定を再生中だけ使用して終了時に戻す。共有のProjectSettingsや他メンバーのアセットは編集しない。Scene_EchoDemo の専用タグ設定もアセットへ移行した。グリッチ用のデモシーン（Scene_EchoGlitchDemo）と専用アセットは削除した。

## 実装と制限

接触領域はGPU上で描画し、メッシュ分割・ベイク・部分Colliderは使わない。既存Colliderの有効状態を変更しない。部分残存は対象ローカル座標の3Dテクスチャに接触時刻を記録するため、カメラの移動や対象の移動で記録が画面上に取り残されない。有限のボクセル精度なので細い面や近接する面では境界に誤差が生じる。ローカル境界サイズや記録解像度の変更時には記録をリセットする。

部分残存のある対象だけRFloatの3D記録領域を確保する。初期値32³は128KiB、64³は1MiB、128³は8MiB/対象（GPUの管理領域等を除く）。このほか1×1の履歴2枚、補助描画面、RenderGraphの一時マスク・接触縮小・元マテリアル描画が必要。同時対象数の要件は確定していないため、実機での上限数は別途Profilerで測定する。特殊な頂点変形や透明・AlphaClipの輪郭は追加対応が必要。部分残存はシェーダーモデル5.0の3D UAV書き込みを使用する。

## 旧方式の整理と確認事項

EchoContactSamplerとGPU読み戻しを廃止したため、Dispose時のWaitForCompletionはなくなった。旧実装では終了時以外の再設定でも待機し得た。旧Initialize/Sample/Submitの数値とbool命名の指摘も処理の廃止により対象外。EchoRevealState / EchoRevealWorld / EchoRevealCollider はMissing Scriptを避ける互換用で、部分衝突判定は行わない。CPU側の旧状態APIに依存するゲームロジックは別途移行が必要。

SO_EchoSurface.assetのベイク結果は新方式では不要。作業開始時のユーザーによる削除を保持した。旧Bakerは過去データの再生成用APIとして残し、依頼された数値をconst化した。2500の重複する実行時利用箇所は廃止済み。旧Bakeの分割は新方式が使わないため対象外。EchoObjectEffectsのシェーダープロパティ指定はIDを使用する。

旧Controllerのシリアライズ値は移行用に保持するが、実行時の表示設定は専用タグアセットのみを読む。移行メニューはOmata_N配下の保存済みシーンだけを対象とする。

## 残存表示の軽量化（2026-10-28）

設定項目・接触解像度・残存精度・更新間隔を維持し、不要な描画を省く。

- 補助RenderTextureはリニアのR8_UNormを明示し、描画対応をSystemInfo.IsFormatSupportedで確認。非対応時はR8G8B8A8_UNormを使い、R8_SRGBの自動フォールバック警告を防ぐ。
- 全体表示または全体残存を使う有効な効果がある場合だけ、全体接触判定を行う。部分表示＋部分残存だけの場合は、3方向のメッシュ描画と接触テクスチャの縮小列を省略する。
- 対象の境界に波が届く可能性がない期間は、部分残存の接触記録と全体接触判定を省略する。記録した時刻の読み出し・失効判定・移動への追従は続ける。
- アウトラインは、その画素に表示がない場合に周辺の境界サンプリングを打ち切る。

全体接触判定が不要な場合、接触解像度1024では3方向の描画に加え5段の縮小パスを省略できる。残存だけの期間には部分記録用の3方向描画も不要になる。実際のFPS改善率は画面内の対象数、メッシュ、使用効果、GPUに依存し、固定の倍率は保証しない。

軽量化後のPlayMode回帰テスト40件がすべて成功（Verification~/PersistenceOptimization.xml）。実行ログにR8_SRGB警告、シェーダーエラー、C#コンパイルエラーがないことを確認した。FPSの比較計測は未実施。
