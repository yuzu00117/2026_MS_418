# デザイナー向け Git ガイド（GitHub Desktop 版）

## 1. Git って何？

| 用語 | たとえ | 意味 |
|---|---|---|
| Git | ゲームのセーブデータ機能 | 作業の途中経過を、好きなタイミングで保存しておく仕組み |
| GitHub | セーブデータの共有クラウド | みんなの保存データをインターネット上に集める場所 |
| コミット | セーブする | 「ここまでの変更」を1回分として記録すること |
| ブランチ | 自分専用のコピー用紙 | 本番のデータを壊さずに、自分だけで作業できる別の道 |
| Push | クラウドにアップロード | 自分のセーブをGitHubに送ること |
| Pull | クラウドから最新を受け取る | みんなの最新の変更を自分のパソコンに取り込むこと |
| PR（Pull Request） | 「本番に混ぜてください」のお願い | 自分のブランチの変更を、みんなの本流に入れてもらう依頼。他のメンバーが確認してから混ぜる |

このチームでは次のブランチを使います（詳しくは [CONTRIBUTING.md の 1. ブランチ戦略](CONTRIBUTING.md#1-ブランチ戦略)）。

- `main` ... 完成版（展示・提出用）。**触りません**
- `develop` ... みんなの作業を集める場所。**直接コミットしません**
- `feature/〜` ... 自分の作業用ブランチ。**作業はここで行います**

> [!CAUTION]
> `main` と `develop` に直接変更を送ること（push）は禁止です。必ず「自分のブランチ → PR → develop」の順で進めます。

## 2. 最初の準備

この準備は最初の1回だけです。

### 2.1 GitHub Desktop をインストールする

1. ブラウザで「GitHub Desktop」と検索し、公式サイトからダウンロードします。
2. ダウンロードしたファイルを開き、画面の案内に従ってインストールします。

### 2.2 サインインする

1. GitHub Desktop を起動します。
2. **Sign in to GitHub.com** を押します。
3. ブラウザが開くので、自分の GitHub アカウントでログインし、許可（Authorize）を押します。
4. 名前とメールアドレスの確認画面が出たら、そのまま **Finish** を押します。

<!-- 画像: GitHub Desktop のサインイン画面 -->

> GitHub アカウントを持っていない場合や、リポジトリに入れない場合は Discord で相談してください。

### 2.3 プロジェクトを自分のパソコンに取り込む（clone）

1. GitHub Desktop の左上 **File** メニュー → **Clone repository...** を選びます。
2. **GitHub.com** タブから `yuzu00117/2026_MS_418` を選びます（見つからないときは **URL** タブに `yuzu00117/2026_MS_418` と入力）。
3. **Local path**（保存先）を決めます。
   - 日本語やスペースを含まない場所がおすすめです（例: `C:\Dev`）。
   - OneDrive や「ドキュメント」など、自動同期されるフォルダは避けてください。
4. **Clone** を押して、終わるまで待ちます（素材が多いので時間がかかることがあります）。

<!-- 画像: Clone repository の画面 -->

### 2.4 Unity でプロジェクトを開く

1. Unity Hub を開き、**Add**（追加）→ **Add project from disk** を選びます。
2. clone したフォルダの中の **`MiraiSozo2027`** フォルダを選びます。
   - 一番外側のフォルダではなく、**`MiraiSozo2027`** です。
3. 追加されたプロジェクトをクリックして開きます。
   - Unity のバージョンが違うと表示された場合は、勝手に変更せず Discord で相談してください。
4. 初回は読み込みに時間がかかります。そのまま待ちます。

<!-- 画像: Unity Hub でプロジェクトを追加する画面 -->

> 完成した素材は `Assets/_Project/` に直接置くので、最初に準備するフォルダはありません（置き場所は [4.5](#45-素材の置き場所) を見てください）。  
> 試作用の個人フォルダ（`Assets/_Sandbox/<自分の名前>/`）は、必要になったときに作れば大丈夫です。作り方は [coding-rules.md の 2.1 個人作業フォルダ](coding-rules.md#21-個人作業フォルダ) を見てください。**フォルダのコピーは必ず Unity の中で行います**（エクスプローラーでコピーしない）。

## 3. 毎回の作業の流れ

作業の流れは次のとおりです。

1. `develop` に切り替えて最新にする
2. 自分用のブランチを作る
3. Unity で作業する
4. 変更を確認してコミット（保存）する
5. Push（アップロード）する
6. GitHub で PR を作る
7. マージされたら確認して次の作業へ

### 3.1 develop に切り替えて最新にする

作業を始める前に、必ず行います。

1. GitHub Desktop 上部の **Current Branch** をクリックします。
2. 一覧から **develop** を選びます。
3. 上部の **Fetch origin** ボタンを押します。
4. ボタンが **Pull origin** に変わったら、それを押して最新の内容を取り込みます。

<!-- 画像: Current Branch から develop を選ぶ画面 -->
<!-- 画像: Fetch origin / Pull origin ボタンの位置 -->

### 3.2 自分用のブランチを作る

1. **Current Branch** をクリックし、**New Branch** を押します。
2. 名前を入力します。形式は次のとおりです。

   ```
   feature/<機能名>
   ```

   例: `feature/title-logo`

   - 機能名は**英小文字とハイフン**で書きます。
   - タスク番号を割り振られている作業なら、`feature/1001_title-logo` のように番号を前に付けます。番号がなければ付けなくて大丈夫です。
   - 名前の付け方は、下の「機能名の付け方」を参考にしてください。
3. 「Create branch from」が **develop** になっていることを確認して、**Create Branch** を押します。

<!-- 画像: New Branch の画面 -->

> 画面上部の Current Branch に、自分のブランチ名が表示されていれば成功です。

#### 機能名の付け方

**「何を」＋「どうする（何の素材か）」**を、英単語2〜3個で書くと分かりやすくなります。

| やる作業 | ブランチ名の例 |
|---|---|
| タイトルロゴを追加する | `feature/title-logo` |
| タイトル画面の UI を作る | `feature/title-ui` |
| ステージ1の背景を作る | `feature/stage1-background` |
| プレイヤーのテクスチャを差し替える | `feature/player-texture` |
| 敵キャラのモデルを追加する | `feature/enemy-model` |
| 敵の歩きアニメーションを作る | `feature/enemy-walk-animation` |
| 爆発エフェクトを作る | `feature/explosion-effect` |
| ボタンなどのアイコン一式を追加する | `feature/ui-icons` |
| 使うフォントを変える | `feature/font-change` |
| ボタンの見た目のずれを直す | `feature/button-design-fix` |

よく使う単語です。

| 日本語 | 英単語 |
|---|---|
| 背景 | `background` |
| ロゴ | `logo` |
| アイコン | `icon` / `icons` |
| 画面・メニュー | `ui` / `menu` |
| テクスチャ・マテリアル | `texture` / `material` |
| 3Dモデル | `model` |
| アニメーション | `animation` |
| エフェクト | `effect` |
| 効果音・BGM | `se` / `bgm` |
| 差し替え・変更 | `change` / `update` |
| 修正 | `fix` |

**避けたい名前の例**

| 名前 | 理由 |
|---|---|
| `feature/タイトルロゴ` | 日本語は使えません |
| `feature/Title_Logo` | 大文字・アンダーバーではなく、英小文字とハイフンにします |
| `feature/yamada` | 人の名前ではなく、作業の内容を書きます |
| `feature/sozai` / `feature/fix` | 何の作業か分かりません |

> 迷ったら、それっぽい名前で大丈夫です。あとから困ることはほとんどないので、作業を止めずに進めましょう。

### 3.3 作業する

Unity を開いて、いつもどおり作業します。

- 先に [4. デザイナーが特に気をつけること](#4-デザイナーが特に気をつけること) を一度読んでください。

### 3.4 変更を確認してコミットする

コミットは「セーブ」です。きりのよいところで行いましょう。

1. Unity を保存して、GitHub Desktop に戻ります。
2. 左側の **Changes** タブに、変更したファイルの一覧が出ます。
3. 一覧を**上から確認**します。
   - 自分が触ったファイルだけか。
   - 同じ名前の `.meta` ファイルも一緒に入っているか。
   - `Library` や `Temp` など見慣れないフォルダが入っていないか（入っていたら [4.3](#43-library-などが-changes-に出たとき) へ）。
4. コミットに含めたくないファイルは、左のチェックを外します。
5. 左下の **Summary** 欄にコミットメッセージを書きます。
6. **Commit to feature/〜**（ボタンにブランチ名が出ます）を押します。

<!-- 画像: Changes タブの画面（ファイル一覧とチェックボックス） -->
<!-- 画像: Summary 欄とコミットボタン -->

#### コミットメッセージの書き方

形式は次のとおりです（詳しくは [CONTRIBUTING.md の 3. コミットルール](CONTRIBUTING.md#3-コミットルール)）。

```
<種別>: <日本語の短い説明>
```

- **1コミット1目的**にします（「ロゴ追加」と「背景の修正」は分ける）。
- 説明は**日本語**で、簡潔に書きます。

デザイナーがよく使う種別の例です。

| 種別 | こんなとき | 例 |
|---|---|---|
| `chore` | 素材（画像・モデル・音など）を追加・差し替えした | `chore: タイトルロゴのテクスチャを追加` |
| `chore` | マテリアルや設定の追加 | `chore: 地面のマテリアルを追加` |
| `feat` | 見た目も含めた新しい機能・演出を追加した | `feat: タイトル画面の UI を追加` |
| `fix` | 見た目の不具合を直した | `fix: ボタンの画像がずれる問題を修正` |
| `docs` | 説明書き・ドキュメントを変更した | `docs: 素材の出典を追記` |

迷ったら、素材の追加・差し替えは `chore` と考えれば大丈夫です。

### 3.5 Push（アップロード）する

1. コミットしたあと、上部のボタンが **Publish branch**（初回）または **Push origin** に変わります。
2. そのボタンを押します。

<!-- 画像: Publish branch / Push origin ボタンの位置 -->

### 3.6 GitHub で PR を作る

1. Push のあと、**Create Pull Request** ボタン（または **Branch** メニュー → **Create pull request**）を押します。ブラウザで GitHub が開きます。
2. **base（マージ先）が `develop` になっている**ことを確認します。`main` になっていたら `develop` に変えてください。
3. タイトルを書きます。コミットと同じ形式です（例: `chore: タイトルロゴのテクスチャを追加`）。
4. 説明欄のテンプレートを埋めます（概要・変更内容・動作確認）。
   - 動作確認のチェックボックスは、**作成時は `[ ]` のまま**にします。PR を作ったあとで、確認できた項目をクリックしてチェックします。
5. **Create pull request** を押します。
6. Discord で「PR を出しました」と連絡し、レビューをお願いします。

<!-- 画像: GitHub の PR 作成画面（base が develop になっている） -->

> 最低 1人の承認がもらえるまで、マージしません。承認後の操作は、レビューした人や担当者に確認してください。詳しいルールは [CONTRIBUTING.md の 4. Pull Request ルール](CONTRIBUTING.md#4-pull-request-ルール) にあります。

### 3.7 マージされたら確認して次の作業へ

**確認する**

1. GitHub の PR ページで、状態が紫色の **Merged** になっていることを確認します。
2. GitHub Desktop の **Current Branch** から **develop** に切り替えます。
3. **Fetch origin** → **Pull origin** で最新にします。
4. Unity でプロジェクトを開き、自分の素材や変更が入っていること、見た目が崩れていないことを確認します。おかしいところがあれば Discord で連絡してください。

<!-- 画像: PR ページの Merged 表示 -->

**使い終わったブランチを削除する**

5. **Current Branch** の一覧で、自分の `feature/〜` ブランチを**右クリック** → **Delete...** を選びます。
6. 「リモートからも削除する」という選択肢が出たら、チェックを入れて削除します。
   - GitHub 側で既に削除されている場合は、操作は不要です。

<!-- 画像: ブランチ一覧で右クリック → Delete の位置 -->

**次の作業へ**

7. 次の作業は、また [3.1](#31-develop-に切り替えて最新にする) から始めます。マージ済みのブランチは使い回さず、作業ごとに新しいブランチを作ってください。

## 4. デザイナーが特に気をつけること

### 4.1 .meta ファイルは必ず一緒にコミットする

Unity は、素材（画像・モデル・音など）1つにつき `.meta` という小さなファイルを作ります。  
これは「素材のIDカード」で、**なくなると他の人の Unity で参照が切れて**、見た目が壊れます。

- 素材を追加したら、`○○.png` と `○○.png.meta` の**両方**が Changes に出ているか確認します。
- `.meta` のチェックを外さないでください。
- 素材を移動・名前変更するときは、**エクスプローラーではなく Unity の Project ウィンドウ上**で行います。

### 4.2 大容量の素材は、コミット前に相談する

動画・高解像度テクスチャ・音源など、ファイルサイズが大きい素材は、**コミットする前に Discord で相談**してください。

- Git LFS（大きいファイル用の仕組み）は、現時点では**使いません**。
- 一度コミットしてしまうと、あとから取り除くのが大変です。

### 4.3 Library などが Changes に出たとき

次のフォルダは、保存（コミット）してはいけません。

- `Library`, `Temp`, `Logs`, `obj`, `UserSettings` など

通常は自動で除外されるので、Changes には出てこないはずです。もし出てきたら、**コミットせず、触らずに**、Discord で相談してください（画面のスクリーンショットを添えると早いです）。

### 4.4 ファイル名のルール

素材のファイル名には、**種類を示す接頭辞**を付けるルールがあります。詳しくは [coding-rules.md の 1.4 アセット命名規則](coding-rules.md#14-アセット命名規則) を見てください。

| 接頭辞 | アセット種類 | 例 |
|---|---|---|
| `PF_` | Prefab | `PF_Player` |
| `M_` | Material | `M_Ground` |
| `T_` | Texture | `T_Ground_Albedo` |
| `AC_` | Animator Controller | `AC_Player` |
| `AN_` | Animation Clip | `AN_Player_Run` |
| `SE_` / `BGM_` | 効果音 / BGM | `SE_Jump`, `BGM_Title` |
| `Scene_` | Scene | `Scene_Title` |

あわせて、次のことをおすすめします（強制ではありません）。

- 英数字を使い、スペースや日本語は避ける（トラブルのもとになるため）。

### 4.5 素材の置き場所

**本番で使うと決まった素材**は、`Assets/_Project/` の中の種類ごとのフォルダに直接置きます。

| 素材 | 置き場所 |
|---|---|
| 3Dモデル | `_Project/Models/` |
| 3D用のテクスチャ | `_Project/Textures/` |
| マテリアル | `_Project/Materials/` |
| UI画像・2D画像 | `_Project/Sprites/` |
| エフェクト | `_Project/Effects/` |
| フォント | `_Project/Fonts/` |
| 効果音・BGM | `_Project/Audio/` |
| アニメーション | `_Project/Animations/` |

**まだ試している途中のもの**は、自分の `Assets/_Sandbox/<自分の名前>/` に置きます。

- 見た目を試している途中の素材、何パターンか作って比べたい素材
- 確認用に作ったシーンや Prefab
- 採用されるか分からない素材

採用が決まったら、**Unity の Project ウィンドウ上で** `_Project/` の該当フォルダへドラッグして移動します（エクスプローラーで移動すると参照が切れます）。

> どこに置けばよいか迷ったら、Discord で相談してください。フォルダの中をさらに分けたいとき（例: `Models/Characters/`）も、先に相談をお願いします。

### 4.6 そのほか

- 他のメンバーの Sandbox フォルダや、他の人が作った共有アセットは、**事前に宣言せず編集しない**でください。
- `Misc` という名前のフォルダは作りません。

## 5. 困ったとき

> **💬 基本方針**: よく分からないときは、**無理に直そうとせず Discord で相談**してください。操作を重ねると、かえって状況が複雑になります。

### 5.1 コンフリクト（衝突）が出た

「Resolve conflicts」や「conflicted files」といった表示が出たら、同じファイルを複数人が変更したということです。

- **シーン・Prefab のコンフリクト**: 手動で合体はしません。どちらか片方を採用し、もう片方は作り直すルールです。**必ず担当者に相談**してください（[CONTRIBUTING.md の 5.2](CONTRIBUTING.md#52-シーンprefab)）。
- **それ以外のファイル**: まず Discord で相談しましょう。

画面を開いたまま、スクリーンショットを撮って連絡すると話が早いです。

### 5.2 間違えて develop でコミットしてしまった

まだ Push していない（アップロード前）なら、直せます。**Push は絶対に押さないでください。**

**直前のコミット1つだけなら**

1. **Changes** タブの左下に出ている **Undo** ボタンを押します（ボタンが見当たらない場合は、自分で操作せず Discord で相談してください）。
2. 変更が Changes タブに戻ります。
3. **Current Branch** → **New Branch** で、`develop` から `feature/〜` を作ります。
4. ブランチ作成後、変更が自分のブランチに引き継がれます。そのままコミットし直します。

変更を持って別ブランチに切り替えるとき、**「Leave my changes on develop」（develop に残す）か「Bring my changes to ○○」（持っていく）** と聞かれたら、**Bring my changes** を選びます。

<!-- 画像: Undo commit の位置 -->
<!-- 画像: Bring my changes to ... の選択画面 -->

**すでに Push してしまった、または複数コミットしてしまった場合**は、自分で直さず、Discord で相談してください。

### 5.3 ファイルが消えた／マテリアルがピンクになった

- **ピンク**: マテリアルやシェーダーの参照が切れています。`.meta` ファイルが抜けている、素材が足りない、などが原因です。
- **ファイルが消えた**: 切り替えや Pull のときに、他のブランチの内容に変わった可能性があります。

どちらも、**自分で作り直したり、ファイルを手で戻したりしないでください**。次のことを調べて Discord で伝えてください。

- どのファイルか（名前と場所）
- いつからか、直前に何をしたか
- GitHub Desktop の Current Branch と Changes の状態（スクリーンショット）

### 5.4 相談の目安

| こんな状態 | 対応 |
|---|---|
| 赤いエラー表示が出た | そのまま Discord に画面を貼る |
| Changes に見覚えのないファイルが大量にある | コミットしない。Discord で相談 |
| Push や PR の操作が分からない | Discord で聞く |
| ずっと同じ画面から進まない | アプリを閉じず、Discord で相談 |
| 自分の変更が消えたかもしれない | 何も操作せず、Discord で相談 |

## 6. PR 前のチェックリスト

PR を作る前に、すべてチェックできるか確認してください。

- [ ] `develop` を最新にしてからブランチを作った
- [ ] ブランチ名が `feature/<機能名>`（英小文字とハイフン）の形式になっている
