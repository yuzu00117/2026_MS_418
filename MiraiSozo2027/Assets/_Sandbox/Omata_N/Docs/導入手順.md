# エコーロケーションの使い方

実装対象はUnity **6000.6.3f1**、URP **17.6.0**、Input System **1.20.0**です。用意されたプロジェクトを指定バージョンで読み込んだ際、Unity標準の更新処理でURP等のパッケージも更新しています。

## まず試す

1. `Assets/_Sandbox/omata/Scenes/Scene_EchoDemo.unity`を開き、再生します。
2. Game Viewをクリックしてフォーカスを当て、**Eキー**を押します。デモはソナーモードで、2秒ごとに現在地から新しい波を出します。各波は設定された伝播時間で広がり、最大半径に到達後3秒残ります。
3. もう一度Eキーを押すと消えます。デモではマウスの戻るボタンとゲームパッド下側ボタン（A／×相当）でも同じ操作ができます。
4. **WASDで移動、マウスを動かすと視点回転、Zキーで一人称／三人称を切り替え**できます。右ドラッグは不要です。
5. **Escでカーソルを解放、Game Viewを左クリックすると再固定**します。カーソル解放中は移動・視点回転を停止します。

青系の薄い色がスキャン済みの表面、明るい帯が波の先端です。空間の境界線でも球・円錐状の範囲を確認できます。波状OFFの場合は内側からオレンジ色の消去波が進みます。

仮プレイヤーはカプセル状の体と頭を持ち、壁・床に衝突するCharacterControllerで動きます。一人称では自分のモデルが画面を塞がないよう影のみを残し、三人称では体が見えます。視点変更でスキャンの中心や半径は変わりません。

デモの赤は敵、緑はアイテム、青は構造物です。灰色の遮蔽物の向こうにある敵も初期設定では表示されます。既存の`Assets/Scenes/SampleScene.unity`は上書きしていません。

## FPS上限を設定する

デモの `Player` を選び、**Echo Frame Rate Limiter → 上限FPS** を変更します。デモと `PF_EchoPlayer.prefab` は初期値 **60FPS** です。30・120・144なども指定でき、再生中の変更も反映します。「FPS上限を有効にする」をOFFにするとPC版の上限を解除します。

Camera／Lightだけのシーンでも、Cameraなど既存のGameObjectに **Add Component → Echo → Frame Rate Limiter** を1つ追加すれば使用できます。Echo Controllerは不要です。Hierarchyに新しいGameObjectを増やす必要はありません。

FPS指定を有効にするため、コンポーネント動作中はVSyncを0にします。コンポーネント自体の無効化・削除・シーンの終了時は適用前のFPS/VSyncへ戻します（他の設定システムが変更した値は戻しません）。複数配置した場合は最初に有効になった1つだけが動作し、重複分は警告して無効化します。別のFPS管理機能とは併用しないでください。

適用はPlay中とビルドしたゲームです。EditorではGameビューが対象で、編集モードやSceneビュー全体の描画を制限するものではありません。FPS指定は目標値であり、負荷・ドライバー・実行環境により実際のFPSは異なります。再生中のInspector変更を保存したい場合は、再生終了後にも値を設定してください。[Unity公式のFPS設定](https://docs.unity3d.com/ja/2023.2/ScriptReference/Application-targetFrameRate.html)

## 自分のシーンへ入れる

1. `PF_EchoPlayer.prefab`を配置するか、プレイヤーへ`EchoController`と`EchoPrototypeInput`を追加します。既存のプレイヤー・カメラがある場合はコンポーネントを追加する方法を使ってください。
2. EchoControllerの「描画カメラ」にゲーム用Base Cameraを指定します。
3. 「スキャン中心」と「正面の基準」を指定します。未指定なら自身のTransformを使用します。視線方向にしたい場合は「正面の基準」にCameraを設定します。
4. 「最大半径」「全開き角」「伝播時間」を設定します。90度なら正面から各方向45度、180度なら半球、360度なら球です。
5. 対象にUnityのタグを設定し、「タグと表示色」に同じタグと色を登録します。色のAが不透明度です。
6. プレイヤー自身が光らないよう「除外するルート」へプレイヤールートを設定します。
7. メニューの **Tools → エコーロケーション → Renderer Featureを設定** を実行します。今回のPC_Renderer・Mobile_Rendererには設定済みです。
8. 「セットアップを検証」を押し、Consoleの案内を確認します。

親のタグで子のモデルをまとめる場合、親に`EchoTarget`を付けます。子に別のEchoTargetがあれば子側のタグを優先します。EchoTargetを付けない場合は各Renderer自身のタグを参照します。

## 操作を変更・追加する

EchoPrototypeInputの「切り替え操作の割り当て」を開き、追加した各行で「機器・操作を選択（日本語）」を押します。Eキー・右クリック・ゲームパッドなどを何件でも併用できます。初めて追加したコンポーネントはEキー1件、デモPrefabは3件です。

「全操作 / パス」ではInput System標準の選択画面から詳細な操作を選べます。パスの鉛筆アイコンから直接編集もできます。詳細選択で軸やマウス変位を選んだ場合は「入力の種類」「軸の負方向」「閾値」も確認してください。日本語メニューから選んだ場合は種類・閾値も自動設定されます。

- ボタン／通常軸：初期押下閾値0.5、再受付閾値0.25。
- マウス移動：初期10ピクセル。ホイール：初期1報告単位。どちらも一度入力が止まってから再受付します。
- 同時に複数押しても1フレームにつき1回だけ切り替えます。
- 押しっぱなしでは繰り返しません。別フレームで別の割り当てを押せば切り替えられます。
- 一覧を空にすると操作なしになります。Eキーが勝手に復活することはありません。

Input SystemはDynamic Updateを使用してください。実行中にInspectorで変更した内容は、再生終了時に戻るUnity標準の扱いです。ゲーム内の設定保存画面は今回の範囲外です。

マウス左ボタンを登録するとUIクリックにも反応します。文字入力・設定画面ではEchoPrototypeInputを無効化してください。同じクリックを物理入力とUI Buttonの両方からToggleScanへ送ると二重操作になります。

## 消え方と壁越し表示

- 「OFF時の消し方 → 即時」：次の描画から消去。
- 「OFF時の消し方 → 手前から順番」：OFF時の外側半径を固定し、中心から同じ速度で消去。
- 「壁越し表示 → 深度で隠す」：壁などシーン深度の手前にある面だけを強調。

波状消去中にONへ戻すと、残っている領域を破棄し、半径0から再開します。「プレイヤーに追従」方式では範囲も移動・旋回に追従し、「ソナー」方式では各波の発生位置・向きが固定されます。

## n秒ごとに波を出し、m秒残すソナー

`Player`の **Echo Controller → スキャン方式 → ソナー（定期再展開）** を選択します。デモとPrefabはこの方式に設定済みです。新規コンポーネントの初期値は互換性のため従来の追従方式です。

| 項目 | 意味 | デモ設定 |
| --- | --- | --- |
| 再展開間隔 n（秒） | ON中に新しい波を出す間隔 | 2秒 |
| 展開後の残存時間 m（秒） | 最大半径への到達後に、その波を残す時間 | 3秒 |
| 伝播時間 z（秒） | 各波が半径0から最大半径まで広がる時間 | 既存の設定を使用 |

ON直後に最初の波を出し、その後n秒ごとに再展開します。各波の中心と向きは発生時に固定され、プレイヤーが移動しても過去の場所に残ります。例えばz=3・n=2・m=3なら、各波の寿命は発生から6秒で、その間に次の波も広がります。

複数の波が重なる場所は一度だけ色を重ね、波の数で強調色が濃くならないようにしています。記録するのはスキャン領域であり、物体の過去の位置を静止画として残す機能ではありません。物体が移動した場合は、現在の表面と残っている領域の交差で判定します。

OFFは新しい波の発生を止めます。「即時」なら全波を消去、「手前から順番」なら各波の外側半径を固定して、それぞれの中心から消去します。OFFの消去処理は通常の残存時間より優先します。方式・半径・角度・伝播時間・n・mの変更は過去の波をリセットします。

nがz+mより長いと、波がない待ち時間ができます。nの最小値は0.05秒です。同時に保持する上限は64波で、それを超える設定では残存時間mを削らず、nを`(z+m)/64`以上へ自動補正します。長いフレーム停止後に過去の位置を推測して大量発生させることはせず、現在地での1回へ集約します。

## 範囲表示とプレイヤーの調整

デモのHierarchyで`Player`を選択します。Hierarchyは`Player`、`View`、`Camera`、`Origin`、`Body`など、短い英語名で統一しています。

- **Echo Range Display**：床・壁への表示／空間の境界線を個別にON/OFFできます。範囲内・拡張波・消去波・境界線の色、波の帯幅を調整できます。コンポーネントを無効にすると範囲の可視化だけ消え、既存のタグ強調は維持します。
- **Echo Demo Player**：移動速度、マウス感度、スティック感度、上下角度制限、三人称の距離・追加高さ、視点切替キーを変更できます。キー変更は次の再生から反映します。
- **Echo Controller**：「スキャン中心」は胴体中央の`Origin`、「正面の基準」は`View`、描画カメラは子の`Camera`です。三人称カメラの位置をスキャン中心にしないでください。

三人称を高くしたい場合は **Echo Demo Player → 三人称の追加高さ（m）** を調整します。初期値0は従来の位置、1ならそこから世界の上方向へ1m、負の値なら下方向です。「三人称の距離」と独立して調整でき、一人称・照準方向・スキャン中心は変わりません。高さを含めた斜めの経路で壁・天井を調べるため、障害物があると指定位置より手前に寄ります。

ゲームパッドでは左スティックで移動、右スティックで視点を動かせます。視点切替もInspectorの入力選択からパッドのボタンへ変更できます。三人称カメラは自分のColliderとTriggerを除外し、背後の障害物に近づいた場合は距離を短縮します。

範囲の表面表示はCameraの深度へ書き込む床・壁などが対象です。深度を持たない透明物や空には色を塗らず、空間は境界線で表現します。タグ対象が0個でも表示され、OFFで消えます。画面外・壁裏の境界線は隠れます。

別シーンで範囲だけ使う場合はEchoControllerと同じGameObjectへEchoRangeDisplayを追加し、Renderer Featureを更新します。仮プレイヤーごと使う場合は更新済みPF_EchoPlayer.prefabを配置してください。床用Colliderが必要です。

既存デモの更新メニューは **Tools → エコーロケーション → デモにプレイヤーと範囲表示を追加** です。今回のデモは更新済みです。更新前のシーンとPrefabはプロジェクト外側の`Artifacts/Before-player-update/`に保存しています。

## 動的生成と外部スクリプト

動的に生成するPrefabにはEchoTargetを付けてください。自動収集だけを使う場合は生成後に`EchoController.RefreshTargets()`を呼びます。子Rendererを追加・差し替えた場合は`EchoTarget.RefreshRenderers()`で再収集してください。LOD構造を変えた場合も再収集が必要です。

入力側から利用するAPIは`SetScanEnabled(bool)`、`ToggleScan()`です。正式なキー設定システムへ移行するときはEchoPrototypeInputを無効化・削除し、新しい入力から同じAPIを呼びます。描画やスキャン処理を書き換える必要はありません。

## 対応範囲

Colliderの種類・有無には依存しません。MeshRendererとSkinnedMeshRendererの表面をワールド位置で判定します。複数サブメッシュ、凹形状、巨大メッシュも同じ経路を使います。

元マテリアルの透明テクスチャによる切り抜き、独自の頂点シェーダー変形は標準では再現しません。Terrain・Sprite・VFX等や別パイプラインには専用の描画拡張が必要です。スキンドメッシュの壁裏更新とboundsは対象の設定も確認してください。

標準構成は単一プレイヤー・1つのBase Cameraです。Scene ViewにはGizmoを表示し、ゲームの強調表示は指定Cameraにだけ描画します。

## ファイルの場所

- `Runtime/Core`：状態・時間・幾何計算・公開API。
- `Runtime/Targets`：タグ・階層所有権・対象登録。
- `Runtime/Rendering`：形状取得・LOD・描画バックエンドの契約。
- `URP`：Render Graphの描画パスとシェーダー。
- `InputSystem`：プロトタイプ入力と専用Inspector。
- `Editor`：日本語Inspector、Gizmo、構成診断。
- `Samples`：デモの作成ツールと移動・操作案内。
- `Tests`：EditMode／PlayModeテスト。

配布前の詳細な確認結果はプロジェクト外側の`Artifacts/検証結果.md`を参照してください。

## エコー地点から見て影になる部分を隠す

Player → Echo Controller → **エコー地点からの遮蔽** を開きます。「影になる部分を強調しない」をONにすると、各エコー地点から壁などの裏にある部分が強調されなくなります。カメラの位置ではなく、エコーが発生した位置から判定します。元の球・扇形、進行速度、n秒ごとの再展開、m秒の残存、OFF消去はそのままです。

**「タグと遮断設定」** に行を追加し、タグと以下のどちらかを選びます。

- **遮断する**：その面の後ろを影にする。壁・地面向け。
- **遮断しない（透過）**：距離を減らさず通す。その先の別の壁では止まる。

デモではEchoStructureを遮断、EchoEnemy／EchoItemを透過に設定しました。未登録タグは「未登録タグは遮断する」で決めます。タグはRendererが付いているGameObjectのものを使います。色のタグ一覧とは別設定です。

同じ物体の一部分だけが影になった場合も、その部分だけを隠します。遮断面そのものは強調できます。プレイヤーの除外ルート配下は影を作りません。壁が動いた場合は毎フレーム影を更新します。古いソナー波は発生位置を保ち、それぞれの位置から影を計算します。

「壁越し表示 → 表示する」はカメラからの壁越し表示です。エコー地点からの影まで無視する設定ではありません。強調対象同士を重ねて両方見せたい場合は、手前側のタグを「遮断しない」にしてください。

「影の解像度」は標準512。境界が粗い場合は1024へ上げられますが、GPU負荷とメモリ使用量が増えます。「表面の誤判定を防ぐ距離」は標準0.03m。小さすぎると表面に影の模様が出やすく、大きすぎると薄い壁を通り抜けて見えます。

MeshRenderer／SkinnedMeshRendererに対応し、ColliderやRead/Write Enabledは不要です。透明マテリアルの穴・独自頂点シェーダー変形・Terrainは対応外です。骨アニメーションを画面外でも更新する場合はUpdate When Offscreenとboundsを確認してください。LightやCameraをHierarchyに追加する必要はありません。
